В этом примере с помощью `filter.filterConfigurationBuilder()` регистрируется несколько конфигураций.

Первая конфигурация делается активной при открытии методом `makeCurrent()`. У условия `age` значение по умолчанию и видимость метки операции заданы прямо на билдере (`defaultValue()`, `operationTextVisible(false)`), а условие `active` получает типизированное значение по умолчанию через `add(component, defaultValue)` (тип проверяется на этапе компиляции). Вторая конфигурация использует корневую операцию `OR` (`operation(LogicalFilterComponent.Operation.OR)`) — премиальный грейд или старший возраст. `buildAndRegister()` отклоняет повторяющийся `id` конфигурации.

Конфигурация, построенная билдером, — это `DesignTimeConfiguration`, как и объявленная в XML. Пользователь может менять значения условий и назначить конфигурацию своей конфигурацией по умолчанию, но не может её редактировать или удалить; чтобы изменить условия, пользователь копирует конфигурацию и сохраняет копию.
